## 1. 总体架构

### 1.1 技术栈与分层

| 层 | 选型 |
|----|------|
| 框架 | Modern.js（React 19 + TypeScript + Rsbuild） |
| 产物形态 | 登录端、用户端、管理后台、安装页均为 SPA（同一工程、四个 entry） |
| 页面外壳 | Go 渲染空壳 HTML，挂载对应 SPA 并注入初始变量（§1.5） |
| WebAuthn | `@simplewebauthn/browser` |
| 契约校验 | 无独立校验层：响应类型全部来自 `@bufbuild/protoc-gen-es` 生成的 TS 消息类型（接口文档 §12.9）；login 表单手写简单校验，admin 表单用 Semi UI 自带校验 |
| 接口调用 | `@connectrpc/connect` + `@connectrpc/connect-web`（浏览器 transport）+ `@bufbuild/protobuf` 运行时 + `@bufbuild/protoc-gen-es` 生成的 TS 消息与 service 类型（见 §3.1） |
| UI 库 | login 端不使用（保证体积）；account / admin 使用 Semi UI |
| Hooks 库 | `ahooks`（获准依赖，版本按落地时最新）；ahooks 已有的能力（useRequest / useDebounce / useLocalStorage 等）不得自行重复封装，自定义 hook 只用于 ahooks 未覆盖的业务逻辑 |

```
浏览器
 ├─ 空壳 HTML（Go 渲染，注入 window.__AUTHLOFT_INIT__，见 §1.5）
 └─ SPA bundle（本工程产物）
      │
      ├─ entry（login / account / admin）：读注入变量 → 建路由 → 挂载
      ├─ pages：页面级容器，只做布局与路由参数
      ├─ flow / containers：状态编排（登录状态机）
      ├─ components(factors / captcha / schema)：按后端下发配置分派渲染
      ├─ shared/api：transport 单例、生成 client、错误归一化（ConnectError → ErrorInfo → §1.6 词汇）、multipart 上传封装
      └─ shared/hooks|utils：能力检测、轮询、倒计时、校验、上传、整数转换
```

### 1.2 抽象边界

能通用的是流程编排，不是交互渲染。

| 层次 | 内容 | 增长曲线 |
|------|------|----------|
| 第一层：完全通用，写一次 | 登录容器 + `challenge → verify → mfa → success` 状态机、方式列表渲染与分组排序、通用字段渲染器（12 种 `type`，见 §3.3）、失败态展示与动作、重试冷却、终点处理 | 恒定 |
| 第二层：每因子一个组件（5 个，`totp` 除外） | `PasswordForm`、`OTPForm`、`WebAuthnButton`、`ProviderButtons`、`RecoveryCodeForm`；`totp` 不设专属组件，由通用 `FormStep` + `CodeInput`（`fields[].type=totp`）渲染 | 恒定，因子种类有限 |
| 第三层：每厂商一个 adapter | 仅 Captcha 需要（各厂商 JS SDK 互不兼容）；`CaptchaWidget` 因 login / account 共用而落在 `shared/`（§3.5） | 低频 |

判定规则（新增认证方式时按顺序判断，不要硬塞进通用 schema）：

1. 用户是敲键盘输入？→ 通用字段渲染器
2. 需要调浏览器原生 API（WebAuthn）？→ 独立组件，只在 `methods` 里声明 `hint` 与能力检测条件。宿主 / 小程序能力（`wx.login`）由宿主自行实现，Authloft 前端不承载
3. 需要等待外部事件（扫码轮询）？→ 独立面板，复用通用轮询 hook
4. 只是跳转？→ 不算组件，后端给 URL 即可

> schema 驱动用来管"有哪些方式、顺序如何、要哪些字段"；不要用它管"怎么和用户 / 浏览器交互"。

新增认证方式时的判定流程与改动清单见 §7。

### 1.3 四 entry 的职责边界

| entry | 挂载路径 | 注入变量（§1.5） | 会话形态 | 主要依赖接口 |
|-------|---------|-----------------|---------|-------------|
| `login` | `/sso/**`、`/auth/**` | `al_root`、`static_base`、`methods`（必填）、`oidc`（可选） | 无会话；`login_token` 仅存内存变量 | 接口文档 §2（SsoService） |
| `account` | `/account/**` | `al_root`、`static_base` | 依赖会话 Cookie（名称 / 属性 / 有效期见接口文档 §1.9；HttpOnly，前端不可读） | 接口文档 §3（AccountService）；另调 `SsoService/Authorize`（`scene=bind`）、`SsoService/CreateQrcode`（`scene=bind`），见 §3.1 |
| `admin` | `/admin/**` | `al_root`、`static_base`（管理员信息由 `AdminService/GetMe` 获取） | 依赖管理员会话 Cookie（复用 SSO 登录，管理员为安装时创建的固定 ID 账号，接口文档 §13） | 接口文档 §5（AdminService） |
| `setup` | `/setup` | `static_base`（仅此一项，不注入 `methods` / `oidc`） | 无会话、无业务态；仅在服务端 setup 模式（无 `config.yaml`）下有意义 | 接口文档 §13（`SetupService`） |

三个业务 entry（`login` / `account` / `admin`）共享 `src/shared`，不得各自复制组件；`login` 与 `account` 共享 `FieldRenderer`、`CodeInput`、`ErrorBanner`、`CaptchaWidget`（因此 `captcha/` 落在 `shared/` 下，见 §3.5）。`setup` entry 与业务端共用同一 connect transport / client 封装（安装模式后端仅注册 `SetupService`，接口契约见接口文档 §13），可复用 `shared/components` 等零依赖组件（见 §6b）。各 entry 的页面与组件必须落对应 `*.module.less`——"不用 UI 库"不等于"不写样式"（样式方案见 §1.7）。

### 1.4 页面渲染分工与路由

- `/api/**` 为接口，其余为页面；页面路由清单与空壳注入约定见接口文档 §8
- `/sso/**`、`/auth/**`、`/account/**`、`/admin/**` → Go 返回空壳 HTML，挂载对应 SPA；路由归属前端
- 两个例外由 Go 直接渲染真实 HTML（"无界面"中转页，不需要 SPA）：
  - `/sso/sync_cookie`：多域名 Cookie 同步的跳转中转页（302，非 SPA）
  - `/sso/logout`：登出，Go 直接处理（接口文档 §2.9）

登录端前端路由：`/sso/login`、`/sso/register`、`/sso/reset`、`/sso/oauth/callback/:provider_key`、`/auth/authorize`。`/auth/authorize` 为 OIDC 授权空壳（§1.3 挂载 `/auth/**`），复用登录页完成授权步骤（"OIDC 授权页即登录页"，见 §4.4 `LoginPage`）；`oidc` 注入见 §1.5，交互见接口文档 §4.2。**有有效会话时该路径由后端直接签发授权码并 302 到 `redirect_uri`，不渲染空壳、不进入前端**；前端只在无会话时渲染空壳完成登录。

安装端前端路由：`/setup`（仅服务端 setup 模式下可达，页面结构见 §6b，接口契约见接口文档 §13）。

### 1.5 初始变量注入（`window.__AUTHLOFT_INIT__`）

首屏就必须有的变量由后端在渲染空壳 HTML 时注入，避免 SPA 再发一轮请求，也避免把配置硬编码进前端。

```html
<script nonce="{{AUTHLOFT_CSP_NONCE}}">window.__AUTHLOFT_INIT__ = {{AUTHLOFT_INIT_JSON}};</script>
<script defer nonce="{{AUTHLOFT_CSP_NONCE}}" src="{{AUTHLOFT_STATIC_BASE}}/login/runtime.a1b2.js"></script>
<script defer nonce="{{AUTHLOFT_CSP_NONCE}}" src="{{AUTHLOFT_STATIC_BASE}}/login/vendor.e5f6.js"></script>
<script defer nonce="{{AUTHLOFT_CSP_NONCE}}" src="{{AUTHLOFT_STATIC_BASE}}/login/entry.c9d0.js"></script>
<link rel="stylesheet" href="{{AUTHLOFT_STATIC_BASE}}/login/entry.3a4b.css">
```

**壳层 HTML 模板由框架构建产物原样复制而来**（2026-11-05 终稿：**绝不自定义模板**，模板唯一来源即 Modern.js 构建产物，`web/` 下不得存在任何自写壳层模板文件，不许两套真相）：每个 entry 取 Modern.js 默认生成的 `dist/html/{entry}/index.html` **原样复制**为后端壳层模板（`server/internal/pages/templates/{entry}.html`，`entry` ∈ `login` / `account` / `admin` / `setup`）——不做结构改写、不删节点、不手工重排、不删 route manifest 等框架生成 HTML 自带的附加物，**框架产物是模板唯一真相源**。`pnpm build` 尾段由同步脚本将构建产物**仅复制**覆盖写入后端目录——三个占位符（`{{AUTHLOFT_STATIC_BASE}}` / `{{AUTHLOFT_CSP_NONCE}}` / `{{AUTHLOFT_INIT_JSON}}`）全部由构建期 config 注入产物，脚本零改写（新口径，取代"三件最小替换"旧口径）。后端运行期只做占位符值替换。**占位符清单、模板落位与 CSP 口径见接口文档 §8（唯一定义，本文不复制）**。

**模板同步脚本与构建期注入口径**（2026-11-05 终稿；脚本归前端仓维护，三个 config 均落 `web/modern.config.ts`）：

- **脚本与依赖**：`web/scripts/sync-templates.mjs`，仅用 node 内置模块（`fs` / `path`），零新增依赖；任何失败（`dist` 缺失、复制异常、对账不过、写入失败）以非零 exit code 结束，供 CI 与 `&&` 链感知
- **仅复制**：每个 entry 将 `dist/html/{entry}/index.html` 原样复制为 `server/internal/pages/templates/{entry}.html`——不做结构改写、不删节点、不手工重排、不删 route manifest、**不做任何改写替换**（含正则 / 文本处理），其余一切保持框架原样
- **三个占位符一律构建期 config 注入**（定稿口径，取代"脚本三件最小替换"旧口径；均落 `modern.config.ts`，同步脚本对产物不做任何替换）：
  ① **nonce 统一挂 = `security.nonce: '{{AUTHLOFT_CSP_NONCE}}'`**（Modern.js / Rsbuild 内建配置）：在标签生成阶段给 `script`（外链 + 内联，含框架自动注入的 runtime / route manifest 内联脚本）、`<style>`、`<link rel="preload" as="script">` 统一挂 nonce 属性，并注入 `import.meta.rspackNonce`（运行期动态插入的 chunk script 同享 nonce）。**已知缺口：不覆盖 `<link rel="stylesheet">`**——由 ③ 的 `html.tags` Handler 一并补挂
  ② **STATIC_BASE 前缀 = `tools.htmlPlugin: { publicPath: '{{AUTHLOFT_STATIC_BASE}}/' }`**：html 插件层 publicPath **仅改写 HTML 内 `script` / `link` 标签的资源前缀**（`@rspack/core` html-plugin 类型注释原文 "The public path used for script and link tags"），**独立于**运行期 publicPath（产物 runtime `f.p="/assets/"` 不变）、CSS `url()` 与异步 chunk 路径——占位符只出现在模板 HTML 文本层，**不会漏进外链 CSS / JS 文件内容**（后端只替换模板 HTML，硬约束）；**生成模板内禁止出现写死的 `/assets`、`/static` 或任何域名**（§9 第 14 条同约束）
  ③ **INIT_JSON = `html.tags` 注入 init script**（A 方案，落位定稿）：为全部 entry 注入标签——`{ tag: 'script', attrs: { nonce: '{{AUTHLOFT_CSP_NONCE}}' }, children: 'window.__AUTHLOFT_INIT__ = {{AUTHLOFT_INIT_JSON}};', head: true, append: false }`，字面形态与本节上方示意一致，`head: true` + `append: false` 使其位于 `<head>` 最前。实证口径（Modern.js 随包文档与构建产物双证）：`html.tags` 与 Rsbuild 用法完全一致（随包文档 `configure/app/html/tags.md`），`children` / `attrs` 原样输出、不做 HTML 转义、不经模板（EJS / lodash）渲染，`{{…}}` 不匹配其语法故原样存活（minify 实测占位符存活；框架产物自带的内联大段 JS 原样输出即实证）；init script 的 nonce 占位符由 attrs 显式携带，与 ① 对 script 的统一挂载同值一致。**落地形态**：因 ① 的 stylesheet 补挂同用 `html.tags`，故取 Handler 形式 `(tags, ctx) => HtmlTag[]`（在 html 标签组处理阶段收全量 head / body 标签并写回）——同一 Handler 内先给 `link[rel=stylesheet]` 补挂 `nonce: '{{AUTHLOFT_CSP_NONCE}}'`，再前插上述 init script 标签一并写回；同步脚本零 INIT 处理
- **为何走构建期 config 而非产物文本改写**：config 在标签**生成阶段直接改写标签流**——不依赖产物 HTML 的文本格式（无正则 / 格式假设）、**天然覆盖框架自动注入的内联脚本**（文本改写须逐版本追踪框架注入点，易碎）、配置项是框架对外接口、跨 Modern.js / Rsbuild 版本更稳（产物文本结构非公开承诺）
- **对账自检（纯校验 fail-fast 义务，脚本零改写）**：复制完成后核对模板内 `script` + `<style>` + `<link rel="stylesheet">` 标签出现数 = `{{AUTHLOFT_CSP_NONCE}}` 出现数，逐个相等，否则整次同步失败——漏挂任意一个标签即整页被 CSP 拦；另校验三占位符均在场、无写死 `/assets` 前缀遗漏；禁止以 `'unsafe-inline'` 放宽
- **风险注记（升级回归义务）**：`security.nonce` 的标签覆盖集（isNonceTag）与 `tools.htmlPlugin.publicPath` 的作用域属 Rsbuild **实现细节、非公开承诺 API**——升级 Modern.js / Rsbuild 时必须回归验证三类标签 nonce 全覆盖与三占位符正常输出；构建期 html-minifier 对 `{{…}}` 占位符 parse 失败会产生**无害 terser 日志噪音**（不影响产物与占位符存活）
- **写入边界**：脚本对 `server/` 的写权限**仅限** `server/internal/pages/templates/{login,account,admin,setup}.html` 四个路径，覆盖式写入；不读不改后端任何 Go 代码，embedfs 消费与渲染归后端（《后端架构》§3.13）
- **命令链**：`web/package.json` 的 `build` 扩为 `modern build && node scripts/sync-templates.mjs`——**本地与 CI 一键口径统一为 `pnpm build`**（构建 + 模板同步一步完成）；另设 `sync:templates` = `node scripts/sync-templates.mjs`，供 dist 未变、仅构建配置改动时单独重跑；CI 侧前端命令即 `pnpm build`，「拷贝 dist → go build」由后端侧衔接（《后端架构》§3.13）；dev 模式由 Modern.js dev server 自渲染，不经同步脚本
- **构建配置配套**：删除 `web/modern.config.ts` 的 `filename.js` 回调（现存逻辑把 initial 非 vendor chunk 固定为 `${name}/entry.js`，属反口径逻辑）、恢复全量 contenthash 的改动仍然成立（§9 第 23 条）；拆包规则（code splitting / 多 chunk）不变

前端侧约束：

- `bootstrap.ts` 读取注入变量；`methods` 必须存在，缺失时渲染错误提示并提示刷新，无回退接口
- **静态资源基址**：`entry.tsx` 在任何动态 `import()` 之前把 `__webpack_public_path__` 设为 `static_base + '/'`（缺省 `/assets/`），此后所有异步 chunk 与图片按该前缀加载；`static_base` 由后台配置（接口文档 §5.6），可为 CDN 绝对地址。**不使用资源版本号**：产物文件名自带 contenthash
- 渠道图标**不做本地文件回落**：`icon` 为空即渲染通用占位（`ProviderIcon`），工程内不存放任何渠道图标资源（接口文档 §2.7.1）
- 首次提交登录请求时，若 `oidc` 存在，以 body 顶层 `oidc` 字段原样回传（仅这一次）
- 前端不得假设其中存在任何凭证：没有会话 ID、没有 `login_token`、没有 Provider 密钥
- 落盘例外仅一处：跳转第三方前把 `oidc` 写入 `localStorage`（键 `al_oidc_ctx`），回调后读出随 body 回传并清除（接口文档 §2.7.2）；多域名同步的链路状态由后端载荷携带，前端不落盘（接口文档 §2.9）
- 注入块的转义、`no-store`、CSP nonce 由后端保证（后端架构 §3.4），前端不做二次信任
- 前端壳层模板须满足接口文档 §8 CSP 终稿：全部 `script`（外链 + 内联）/ `<style>` / `<link rel="stylesheet">` 标签统一携带 `{{AUTHLOFT_CSP_NONCE}}` 占位符（由构建期 `security.nonce` + `html.tags` Handler 注入，同步脚本仅复制并对账 fail-fast，见本节）；`eval` / `new Function` 禁止；禁止以 `'unsafe-inline'` 放宽；源代码层面样式仍一律 `*.module.less` 外链产物（编码约束见 §9 第 22 条）

### 1.6 第三方库

- 公共依赖（所有 entry 均可使用，含 login）：`react`、`@bufbuild/protobuf`、`@connectrpc/connect`、`@connectrpc/connect-web`、`@simplewebauthn/browser`、`ahooks`（获准依赖，版本按落地时最新；按 hook 粒度 tree-shaking 引入，login 端同样适用）
- ahooks 已有的能力（useRequest / useDebounce / useLocalStorage 等）**不得自行重复封装**；自定义 hook 只用于 ahooks 未覆盖的业务逻辑（§9 第 19 条）
- 除公共依赖外，login 不可依赖其他第三方库，以确保首屏性能最优
- account 及 admin 使用 [Semi UI](https://semi.design/zh-CN/start/getting-started)；可适当使用其他第三方库以减少重复开发
- **Semi UI 包名（硬性口径）**：只允许 `@douyinfe/semi-ui-19`（React 19 兼容版）；`package.json` 中 semi 相关依赖**仅此一个**，禁止新旧两个 semi 包并存（并存 = 双份体积与样式冲突）
- **Semi UI 导入方式（硬性口径，同上）**：一律从大包入口导入——`import { Button } from '@douyinfe/semi-ui-19'`（或默认导入）；**禁止任何子路径导入**（`@douyinfe/semi-ui-19/lib/es/...` 一律不许）。理由：Rsbuild 自动 tree shaking，大包导入不会把整库打进产物；子路径破坏导入一致性，包升级时易碎。此前「以 lib/es 子路径规避 rstest chunk bug」的裁量记录就此废止，以本口径为准。**纯 `import type` 豁免（受控例外，不削弱上述禁令）**：须同时满足四条件——① 仅类型导入（纯 `import type`，编译期擦除，零运行时产物）；② 子路径在包 `exports` 白名单内（如 `./lib/es/table`）；③ 大包入口确未转出该类型（实证：`lib/es/index.d.ts` 对 Table 仅 `export { default as Table }`，无 `ColumnProps`；泛型 `ColumnProps<T>` 亦无法经 `ComponentProps<typeof Table>` 等价提取，泛型会退化为默认参数丢 `T`）；④ 使用处注释标记豁免依据（如 `DataTable.tsx` 的 `ColumnProps`）。四条件缺一不可；包升级导致的类型路径破坏由 `tsc` 编译期兜底
- 样式零新增依赖：`less` / `less-loader` 系 Modern.js 构建链内置传递依赖（`@modern-js/app-tools → @modern-js/builder → @rsbuild/plugin-less`，pnpm-lock 实证），`package.json` 不新增任何样式包；样式方案见 §1.7，禁止引入 CSS-in-JS、Tailwind、UnoCSS

### 1.7 样式方案（CSS Modules + Less）

自定义样式统一用 module less（Modern.js 原生支持，`.module.less` 文件默认按 CSS Modules 处理，无需任何构建配置，loader 自定义需求才用 `tools.less`）。

- **一律 CSS Modules**：组件样式文件与组件**同目录同名**，命名 `Xxx.module.less`（如 `LoginContainer.tsx` ↔ `LoginContainer.module.less`）
- **零新增依赖**：`less` / `less-loader` 系构建链内置传递依赖（见 §1.6），项目不需要安装任何样式包；禁止引入 CSS-in-JS（styled-components 等）、Tailwind、UnoCSS
- **全局 CSS 唯一例外**：`shared/styles/`（`tokens.less` 设计令牌 + `reset.less` 基础重置）——只存变量与基础重置，**禁止组件选择器**；由每个 entry 的 `entry.tsx` 顶部 import 一次。共享变量引用：组件的 `*.module.less` 顶部 `@import (reference) '../../shared/styles/tokens.less';`（`reference` 不重复产出 CSS），随后使用 `@color-primary` 等 less 变量
- **类名 camelCase**：tsx 内以 `styles.pageTitle` 方式取用；`:global()` 仅限与 Semi UI 或第三方 DOM 结构对接处，须同行注明理由
- **禁止内联样式做布局**（tsx `style={{...}}`）；按运行期数据动态计算尺寸等少数场景允许，须注释说明
- **"不用 UI 库" ≠ "不写样式"**：login / setup 端不引任何 UI 库，但其页面与组件必须落 `*.module.less`（见 §1.3）；account / admin 的 Semi UI 自带组件样式，页面级布局与自定义样式仍按本节执行
- **涉 UI 改动的验收追加项**（不替代既有 `tsc / rs test / rs lint / pnpm build`）：须检查——① 页面 / 组件存在对应 `*.module.less` 且被 import；② `pnpm build` 产物 `dist/**` 出现 `.css` 文件

## 3. `shared/` 文件职责

### 3.1 `shared/api`

> 报文类型**只有一个来源**：`src/gen/proto`（`@bufbuild/protoc-gen-es` 由后端同一批 `.proto` 生成，接口文档 §12.9）。组件与业务代码只使用生成的消息类型，禁止手写接口 interface，禁止在 `shared/api` 里重新描述字段。

| 文件 | 职责 | 关键约束 |
|------|------|---------|
| `http.ts` | transport 单例（`createConnectTransport({ baseUrl: al_root, credentials: 'include' })`）+ 超时 / 中断注入 + 生成的 service client 构造；非 2xx 由 connect-es 抛 `ConnectError`，`findDetail(ErrorInfo)` 解出业务细分码归一为 `ApiError`；multipart 仍走 `postForm(url, formData)`（签名另可选 `onUploadProgress`；REST 豁免端点，不用 transport） | transport 与 client 只在此构造（见下方"transport 与错误归一"）；组件不得裸 `fetch`、不得自己 `JSON.parse` 业务报文；不自行加自定义头触发预检；`postForm` 的 `Content-Type` **不手动设置**（交由浏览器带 boundary） |
| `errors.ts` | 两层错误口径（§1.6 词汇、两个位置）：① 登录流程域 200 响应顶层 `status`（含 `next` / `mfa_required` 等流程态）→ `{retryable, action, i18nKey}`；② 其余域 `ConnectError` 的 `ErrorInfo.code`——无 detail 时按 Connect 标准码（§1.5）兜底，统一拦截文案 | 不存在第二套业务错误码；未知取值走兜底文案，不暴露内部信息；`ErrorInfo.message` / `ConnectError.message` 只作兜底 |
| `types.ts` | 从 `src/gen/proto` re-export 的 `methods` 快照、`schema`、`thirdparty.providers`、`ErrorInfo` 等类型别名 | 全部结构的唯一定义在《接口文档》与 `.proto`；缺类型时先补 `.proto` 再生成，禁止双份手写 |
| `sso.ts` | 跨 entry 复用的 SsoService client 方法薄封装（`Authorize`、`CreateQrcode`、`CreateCaptchaImage`；account 的绑定与 captcha，见接口文档 §3.7.1） | 只放被 ≥2 个 entry 使用的调用；login 专属调用仍留在 `login/api.ts` |
| `account.ts` | 跨 entry 复用的 AccountService client 方法薄封装（`GetConfig`、`ThirdpartyOauth`；login 的 `OAuthCallbackPage` 走 `b` 前缀分支时使用，接口文档 §2.7.3） | 同上：只做薄封装，不承载业务分支 |

**transport 与错误归一**

- 请求 / 响应编解码由 connect-es transport 承担（JSON：标准 protojson 映射——lowerCamelCase、省略零值、int64 十进制字符串，接口文档 §1.1 / §1.12）；组件与业务代码只接触生成的消息对象
- 对缺失字段按零值兜底：`msg.field ?? 零值`，禁止假设字段恒存在
- 错误归一化：非 2xx → `ConnectError` → `findDetail(ErrorInfoSchema)` 取 `{domain, code, message, retryAfter, attemptsLeft}` → 抛 `ApiError`；登录域 200 的流程 `status` 分支仍走业务层（`reducer`），不在 transport 拦截
- 头像直传（REST 豁免）与 `direct` 模式的对象存储 `PUT` 不走 transport，见 §3.2 `useUpload`

**数字（接口文档 §1.12）**

- 生成的消息里 `int64` 字段是 `bigint`，JSON 文本里是十进制字符串——转换由 connect-es（`@bufbuild/protobuf`）完成，业务代码两端都见不到字符串
- ID / 时间戳全程保持 `bigint` 或字符串，**禁止 `Number(id)`**（超 2^53 静默丢精度）；展示用 `shared/utils/int.ts` 的 `toDisplay`
- 时长 / 计数类（`retryAfter`、`expiresIn`、`pageSize`、`total`、`length`）可用 `utils/int.ts` 的 `toCount` 转 `number`，转换处自带 `Number.MAX_SAFE_INTEGER` 断言

### 3.2 `shared/hooks`

| 文件 | 职责 | 关键约束 |
|------|------|---------|
| `useLongPoll.ts` | 长轮询：单次最长等待、超时立即重连、指数退避、页面卸载 / 组件卸载中断、错误上限后停止并回调 | 被 `QRCodeStep` 与 ticket 完成登录复用；必须在 `unmount` 时 abort |
| `useCountdown.ts` | 基于 `retryAfter` / `expiresIn` 的秒级倒计时，暴露 `seconds` 与 `expired`；入参为生成消息里的 `bigint`，内部经 `utils/int.ts` 的 `toCount` 归一为 `number` | 用时间戳而非递减计数，避免后台标签页节流导致漂移 |
| `useRequest.ts` | 请求状态封装（`idle/loading/success/error`）+ 竞态丢弃 + 手动 `reset` | 禁止并发提交同一 step；提交中禁用按钮 |
| `useCapability.ts` | 按 `methods[].capability` 表达式做能力检测：表达式按 `.` 拆分为属性链，从 `window` 起逐段取值（如 `window.PublicKeyCredential`），整链解析成功且末段为真值 → `true`；任一段缺失 / 非对象 / 表达式非法 → `false`。**禁止 `eval` / `new Function`**（页面 CSP 不含 `unsafe-eval`，会被浏览器阻断；能力表达式不构成可信输入） | 能力不满足则该方式自动隐藏（需求 §4.1.6），不展示"不支持"提示；解析失败一律按不支持处理，不抛错 |
| `useUpload.ts` | 统一 `upload(file, scene) → url`：读 `AccountService/GetConfig` 的 `avatarUpload.{mode,maxSize,allowedTypes}`（经 `shared/api/account`；`mfaPolicy` 不由本 hook 消费，安全中心按接口文档 §3.2 读取），在 proxy / direct 间切换（接口文档 §10.8） | 模式差异只收敛在此 hook 内；上传前做体积 / 类型预校验，文案与后端一致；仅用于头像（渠道图标不允许在 Authloft 内上传） |
| `useCopy.ts` | 剪贴板复制 + 短暂成功态 | 用于 provider_key、回调地址、恢复码复制 |

上传两种模式（统一流程与适用场景**见接口文档 §10.8**，本文不复述步骤与端点顺序），由后端下发 `mode` 决定，前端分支只有两处：

- `proxy`：调 `http.ts` 的 `postForm('/api/account/avatar', formData)`，用其 `onUploadProgress` 显示上传进度
- `direct`：`useUpload` 取 `uploadUrl` 与 `headers` 后 `fetch(uploadURL,{method:'PUT'})` 直传（不带 Cookie），`CommitAvatar` 返回 `url` 后才回填头像

直传需业务方在对象存储侧配置 CORS（部署事项）。

### 3.3 `shared/components` 与 `shared/app-ui`

`shared/components` 只放**零第三方 UI 依赖**的组件（login 直接引用也不增加包体）；依赖 Semi UI 的共享组件统一放 `shared/app-ui/`，仅 account / admin 可 import（§9 第 13 条）。

| 文件 | 职责 | 关键约束 |
|------|------|---------|
| `FieldRenderer.tsx` | 通用字段渲染器，按后端下发的 `fields[]` 渲染；12 种 `type` 的取值与含义**见接口文档 §1.11**（唯一定义） | 只吃后端下发的 `fields[]`；禁止在组件内硬编码任何业务字段；未知 `type` 走兜底渲染 |

状态机（接口文档 §1.3 的 `status` 即状态）：

```
idle → (选方式) → challenge? → verify → [mfa_required] → challenge? → verify → success
                                    ↘ [binding_required] → 绑定选择页 → success / 退出重登
                                    ↘ [captcha_required] → 原地插入 CaptchaWidget
                                    ↘ [too_many_requests|locked|failed] → 失败态（按接口文档 §1.6 出动作）
```

非 success 即失败（扫码轮询的 `pending` / `scanned` 为进行中，不作失败处理，见接口文档 §1.6）。

`login_token` 的传递规则与覆盖语义**见接口文档 §1.8、§1.3**（唯一定义）。前端实现五条，不可打折：

1. 由 `loginTokenStore` 以模块级变量保存；前端不解析其内容，只做"收到就替换、请求就带上"
2. 每次响应若含 `login_token`，无条件覆盖内存变量（后端每次重签，旧值立即作废）
3. `status=success` 时清空
4. 禁止写入 `localStorage` / `sessionStorage` / Cookie
5. 页面刷新 → 内存变量丢失 → 自动回到登录第一步，并提示"登录已超时，请重新开始"

其他编排约束：

- `status=mfa_required` 时原地渲染 `mfa.methods` 的选择器 + 对应因子组件，不跳页、不新开流程
- 轮询统一走 `useLongPoll`（指数退避、页面卸载中断）
- 全程受 `login_token` 10 分钟有效期约束，超时回到第一步

小程序 / 宿主环境差异：无 Cookie，Authloft 在响应体下发 `session_token`（接口文档 §1.2），宿主后续用 Header `X-Authloft-Token` 回传；`login_token` 处理与浏览器端一致（响应体返回 → 内存变量 → body 回传）。宿主侧交互与页面不在本工程（§9 第 10 条）。

### 4.2 步骤分派（`steps/`）—— 对应 `next_step.kind`

## 9. 编码约束（写进 lint / review checklist）

1. 禁止 `localStorage` / `sessionStorage` / `document.cookie` 的写入；豁免仅：`login/oidcContext.ts`（键 `al_oidc_ctx`，只存 OIDC 上下文）
2. 禁止在通用层出现任何具体 `method` 字符串（如 `'otp_sms'`），只能出现在 `factors/registry.ts`
3. 禁止在组件内硬编码渠道名、字段名、失败文案，接口走统一封装；一律按 `status` 查 i18n 或取后端下发（`error.message`）
4. `fields[]` 的校验规则以下发为准，前端只做体验性校验（后端是唯一权威）
5. 所有**发往本系统接口**的请求由 `http.ts` 的 transport / client 统一发出（multipart 上传走 `http.ts` 的 `postForm`），不允许组件内裸 `fetch`。唯一豁免是 §3.2 `direct` 分支的直传 `PUT`（目标是对象存储的临时 URL，不带 Cookie 与本系统凭证，不经过本系统接口）
6. `login_token` 只经 `api.ts` 读写，业务组件不得直接触碰 `loginTokenStore`
7. 轮询必须可中断；倒计时必须基于时间戳
8. 新增能力时先走 §7 的判定表；若需要改 `LoginContainer` / `reducer` 才能接入，视为设计问题而非实现问题
9. 分支只认 `status` / `ErrorInfo.code`：取值必须落在接口文档 §1.6 的封闭集合内；禁止在前端定义任何业务错误码常量或按错误码分支（Connect 标准码兜底文案除外）
10. 小程序 / 宿主能力不在本工程实现：`login/` 下不得出现 `wx.*`、宿主桥接或 `external` 步骤组件
11. captcha 配置只由调用方注入：`shared/captcha/CaptchaWidget` 不发配置请求；首屏 login 传注入快照的 `methods.captcha`、account 传 `AccountService/GetConfig` 的 `captcha`，运行期以响应顶层的 `captcha` 覆盖（接口文档 §2.5）——`captcha` 对象不得被缓存为模块级常量
12. 三方回调按 `state` 首字母分派，不在前端判业务：`l` 走登录接口、`b` 走绑定接口；`OAuthCallbackPage` 只转发，不解析、不落盘、不自行决定跳哪个业务页
13. entry 边界由 lint 固化（Rslint，Rstack 体系自带，规则配置接入时补齐）：`login/` 禁止 import `account/`、`admin/`、`shared/app-ui/`、`@douyinfe/semi-ui-19`；`shared/` 禁止 import 任何 entry；跨 entry 复用只经 `shared/api`、`shared/hooks`、`shared/utils`、`shared/components`、`shared/captcha`
14. 静态资源 URL 只由 `static_base`（注入变量）拼出：禁止写死 `/assets`、`/static` 或 CDN 域名；`__webpack_public_path__` 只在 `entry.tsx` 赋值一次
15. 报文类型只来自 `src/gen/proto`：禁止手写接口 interface、禁止在组件里 `as` 断言出字段；`src/gen` 产物禁止手改
16. transport 与 client 只在 `http.ts` 构造：禁止组件内 `JSON.parse` / `JSON.stringify` 业务报文、禁止手拼 `Blob` 发请求；编解码选项禁止改写（标准 protojson，接口文档 §1.1）
17. 数字只经 `utils/int.ts` 转换：禁止 `Number(id)`、禁止对 `bigint` 做隐式字符串比较；提交给后端的整型由序列化层输出字符串，禁止手写 `String(n)` 拼 JSON
18. 对缺失字段一律按零值兜底（`?? 零值`）：标准 protojson 省略零值字段（接口文档 §1.1），禁止假设响应字段恒存在
19. Hooks 优先用 `ahooks`（获准依赖）：useRequest / useDebounce / useLocalStorage 等已有能力**禁止重复造轮子**；自定义 hook 只用于 ahooks 未覆盖的业务逻辑
20. 样式一律 CSS Modules + `*.module.less`（与组件同目录同名、类名 camelCase、禁止内联样式做布局、`:global()` 须注明理由）；全局 CSS 仅限 `shared/styles/`（见 §1.7）；禁止引入 CSS-in-JS / Tailwind 等任何样式依赖——**"不用 UI 库"不等于"不写样式"**，login / setup 端同样必须落样式
21. Semi UI 一律从 `@douyinfe/semi-ui-19` 大包入口导入（具名或默认导入），禁止任何子路径（`/lib/es/...` 等）；`package.json` 只允许这一个 semi 包，禁止新旧并存（硬性口径见 §1.6）；**纯 `import type` 豁免（受控例外）**：仅类型导入（编译期擦除）+ 子路径在包 `exports` 白名单 + 大包入口确未转出该类型 + 使用处注释标记，四条件齐才允许子路径（如 `DataTable.tsx` 的 `ColumnProps`，细则与查证见 §1.6）
22. 壳层模板 CSP 产物自查（口径随 §1.5 同步纠偏）：壳层模板由框架构建产物原样复制而来，其中 `script`（外链 + 内联，含框架生成的内联 runtime / route manifest 脚本与 init script）、`<style>`、`<link rel="stylesheet">` 标签若存在必须全部携带 `{{AUTHLOFT_CSP_NONCE}}` 占位符——**漏挂任意一个即整页被 CSP 拦**；nonce 注入由构建期 config 保证（`security.nonce` 统一挂 script / style / preload，`html.tags` Handler 补 `link[rel=stylesheet]` 缺口，见 §1.5），同步脚本**零改写**、仅承担对账校验 fail-fast 义务（模板内三类标签出现数 = nonce 占位符出现数，逐个相等，否则整次构建失败），禁止以 `'unsafe-inline'` 放宽；产物层面 `eval` / `new Function` 仍禁止。review 增查项：同步对账通过、产物内无裸奔（未挂 nonce）标签，nonce 由构建期 config 统一注入、业务代码不手写
23. **禁止在构建配置的 filename / output 钩子里去除文件名 hash**：产物文件名一律保留 contenthash，多 chunk 引用由同步脚本按构建产物动态生成、不硬编码文件名（见 §1.5）；缓存失效由 contenthash 文件名 + 壳层 `no-store` 承担（接口文档 §8）
