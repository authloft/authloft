# 用户中心系统（Authloft）需求文档

---

## 1. 项目目标

构建一套**统一用户中心（Authloft）**，实现：

1. **统一身份池**：集中管理用户账号、资料与登录凭证
2. **多方式登录**：账密、一次性验证码、通行密钥、第三方账号，以及两步验证
3. **第三方登录接入**：支持主流社交 / 企业账号一键登录
4. **标准协议对外**：完整支持 OIDC，为业务系统提供身份服务
5. **可扩展性**：第三方登录、人机校验、短信、邮件、存储等能力均为**可插拔的提供方（Provider）**，由管理后台动态配置，新增渠道无需改动系统

---

## 2. 设计原则（影响产品形态的四条）

| 原则 | 对产品的意义 |
|------|--------------|
| 统一管理各类外部服务 | 第三方登录、人机校验、短信、邮件、文件存储均在同一处配置，体验一致 |
| 以"提供方标识"引用 | 系统各处只引用一个配置标识，切换厂商（如换短信服务商）只需改配置，不改功能 |
| 可插拔 | 新增一个渠道 / 厂商，是"新增一项配置"，不是"新增一个功能" |
| 配置即时生效 | 后台修改配置后无需重启系统即可生效 |

> 前端呈现（登录页有哪些按钮、每种方式要填什么、点下去发生什么）由后台下发的配置决定，不在代码中写死。

---

## 3. 术语

| 术语 | 含义 |
|------|------|
| 提供方（Provider） | 一类外部服务的具体接入配置，如"阿里云短信""Cloudflare 人机校验""QQ 登录""对象存储"。每类可有任意多个，互不影响 |
| 提供方标识 | 该项配置的唯一代号，用于被其他配置引用 |
| 认证因子 | 一种证明身份的凭证，如密码、短信验证码、邮箱验证码、通行密钥、动态口令（TOTP）、第三方账号 |
| 主因子 / 二次因子 | 登录时用的第一重凭证 / 两步验证用的第二重凭证。同一因子可只作主因子、只作二次因子，或两者皆可 |
| 人机校验 | 图形验证码或第三方无感校验（如 Cloudflare Turnstile、Google reCAPTCHA），用于区分人与机器 |
| 通行密钥 | 基于设备生物识别 / 硬件密钥的无密码登录方式（WebAuthn 标准） |
| 业务系统 | 通过 OIDC 接入 Authloft 的第三方应用 |

## 4. 功能性需求

### 4.1 账号与凭证

#### 4.1.1 账号标识

- 用户注册时，**手机号与邮箱至少绑定一项**，且全系统唯一（用户名 + 密码注册方式下可暂不绑定，后续在安全中心补绑，见 §4.1.2）
- 用户名必选，设置后可用于登录，全局唯一。仅可包含字母、数字、下划线，且长度在 5-20 个字符之间。设置后不可修改。
- 登录框接受"用户名 / 邮箱 / 手机号"任一形式

#### 4.1.2 注册

- 注册方式：手机号注册、邮箱注册（均需通过**一次性验证码**验证归属）、用户名 + 密码注册（见下）
- 注册时可设置密码，密码需满足强度策略：**长度 ≥ 8，且包含大写字母、小写字母、数字**
- 用户名 + 密码注册：一步提交用户名、密码与人机校验，无需验证码；**默认开启**（系统第一个注册成功的用户即管理员，规则见接口文档 §5），管理员可在后台单独关闭
- 注册入口可整体关闭；手机号注册、邮箱注册、用户名 + 密码注册可分别关闭（开关键与默认值见接口文档 §5.6）
- 通过第三方账号首次登录时，可免密创建账号（详见 4.3）

#### 4.1.3 登录方式

系统支持以下登录方式，**每一种均可单独开启或关闭**：

| 方式 | 说明 |
|------|------|
| 账号 + 密码 | 支持用户名 / 邮箱 / 手机号 + 密码 |
| 短信验证码 | 输入已绑定手机号，收取验证码登录 |
| 邮箱验证码 | 输入已绑定邮箱，收取验证码登录 |
| 通行密钥 | 使用设备上的通行密钥登录，无需输入账号 |
| 第三方账号 | 详见 4.3 |
| 通过已登录设备 | **不直接对外暴露**，仅作为底层通用能力（同一浏览器已登录时免重复登录） |

- **两步验证（MFA）**：可整体开关，并可按因子分别开关（动态口令 / 短信 / 邮箱 / 通行密钥）
  - 用户可在安全中心**选择启用其中一项或多项**；启用任意一项后，该用户登录时必须在主因子通过后，再选一种已启用的方式完成二次验证
- **动态口令（TOTP）**：绑定时生成恢复码，供设备丢失时应急使用；恢复码一次性消费

#### 4.1.4 人机校验（Captcha）

- 人机校验统一作为一种可配置的提供方，可配置多个，但全局只启用一个
- 至少需支持：**系统自绘图形验证码**、以及可配置的第三方无感校验（Cloudflare Turnstile、Google reCAPTCHA 等）
- 无第三方服务可用时（未配置 / 全部禁用 / 健康检查失败），服务端自动回退到自绘图形验证码：同一套接口与提交格式，下发的配置 `type=image`；前端按下发的 `type` 渲染，无需刷新页面（定义见接口文档 §2.5）
- **触发规则**：
  - 发送一次性验证码前，**每一次下发都必须通过一次人机校验**（含两步验证阶段的下发）
  - 密码登录：同一账号当日累计失败达到阈值（默认 3 次）后，后续登录必须携带人机校验
  - 阈值可在后台调整；调整仅对调整之后的登录行为生效
- 校验凭据一次性使用，不可重复提交

#### 4.1.5 一次性验证码

- 用途：登录、注册、重置密码、绑定手机号 / 邮箱、两步验证
- 规则：
  - 验证码为 6 位数字，有效期、重发冷却、日限额与失败次数上限均为可配置项（键名与默认值见接口文档 §5.6），校验成功即失效
  - 同一目标在冷却期内不可重复发送；单目标、单 IP 每日发送次数有上限（可配置）
  - 验证码与"用途"绑定：登录收到的验证码不能用于重置密码
  - 校验失败次数有限，超限该验证码立即作废
  - **未绑定该手机号 / 邮箱的用户，不允许用该方式登录**，直接返回明确错误提示

#### 4.1.6 通行密钥（WebAuthn）

- 用户可在安全中心注册多个通行密钥（设备 / 浏览器 / 硬件密钥）
- 仅支持免用户名登录模式：直接选择设备上已保存的通行密钥
- 通行密钥既可作为主登录方式（免密），也可作为两步验证方式
- 浏览器或设备不支持时，该方式自动不展示
- 注册通行密钥要求创建"可发现凭据"，以支持免用户名登录

#### 4.1.7 登录失败保护

- 不做"失败 N 次锁定账号"，改为渐进式限制（默认值均可在后台调整）：
  1. 同一账号当日累计密码错误 **3 次** → 后续登录必须携带人机校验
  2. 继续累计失败 **6 次** → 暂时禁止该账号使用密码登录 **6 小时**
- 计数以账号维度统计；账号不存在时按"IP + 输入账号"统计
- 更换网络、更换设备均不重置当日累计
- 管理员可在后台手动解除限制

#### 4.1.8 密码重置

- 前提：用户已设置密码，且已绑定邮箱或手机号
- 流程：验证邮箱 / 短信验证码 → 设置新密码（需满足强度策略）
- 重置成功后，**该用户所有会话与已颁发的令牌全部失效**
- 入口可整体关闭：是否开放由 `allow_password_reset` 控制（键名与默认值见接口文档 §5.6）

#### 4.1.9 密码策略

- 强度：长度 ≥ 8，含大写字母、小写字母、数字（可配置项与默认值见接口文档 §5.6）
- 修改密码需验证当前密码（已登录状态）
- 无密码的账号可直接设置密码
- 修改密码后，当前会话与令牌全部失效

### 4.2 用户资料与安全中心

#### 4.2.1 资料管理

- 用户资料包括：用户名、手机号、邮箱、头像、昵称等
- 用户可自助修改昵称、头像
- 修改 / 绑定手机号或邮箱，必须通过一次性验证码验证新号码归属
- 头像上传走可配置的文件存储提供方；上传方式（经系统转发 / 直接传到存储）由系统配置决定

#### 4.2.2 安全中心（用户自助）

| 功能 | 说明 |
|------|------|
| 修改密码 | 验证当前密码后设置新密码 |
| 绑定 / 换绑手机号 | 验证新号码验证码 |
| 绑定 / 换绑邮箱 | 验证新邮箱验证码 |
| 两步验证管理 | 启用 / 停用动态口令、短信、邮箱、通行密钥；查看并重新生成恢复码 |
| 通行密钥管理 | 注册、重命名、删除 |
| 第三方账号绑定 | 绑定 / 解绑第三方账号；解绑后仍持有密码凭证，或仍绑定至少 1 个非 Union 第三方渠道时方可解绑 |
| 登录日志 | 查看本人近期登录记录（时间、方式、IP、设备UA） |

### 4.3 第三方登录

#### 4.3.1 支持接入的渠道

QQ、支付宝、飞书、微博、百度、微信开放平台、微信小程序（接口）、微信小程序（扫码）、GitHub、Gitee、Microsoft Online、Google。

> 此外需支持**标准协议兜底**：任何符合 OIDC 或 OAuth2 标准、但未在清单中的渠道，应能通过后台填写若干地址完成接入，无需开发。

#### 4.3.2 登录流程

1. 用户在登录页点击第三方图标 → 跳转至第三方授权页（或在宿主环境内唤起授权）
2. 授权成功后回到 Authloft，取得该渠道下的用户唯一标识（可配置优先使用跨应用统一标识）
3. 查询绑定关系：
   - **已绑定** → 直接登录
   - **未绑定** → 提示"首次登录"，由用户选择：
     - **退出，使用其他账号登录**：退出当前会话，返回登录页，用户可选择其他账号登录
     - **创建新账号**：输入用户名后，免密创建账号并完成登录
   - 可针对每个渠道单独配置"是否允许注册"；关闭后该渠道不得用于建号：未绑定用户经该渠道登录仍进入"首次登录"页，前端将"创建新账号"置灰（只保留"退出，使用其他账号登录"并提示该渠道未开放注册），不提供"绑定已有账号"分支
4. 若该用户已启用两步验证，第三方登录同样需要完成二次验证（第三方账号只替代主因子）
5. 完成 Authloft 内部登录；若为业务系统发起的 OIDC 登录，则继续返回业务系统

#### 4.3.3 渠道级配置

- 每个渠道可单独配置：是否启用、是否允许登录、是否允许注册、是否按邮箱 / 手机号自动绑定已有账号（默认关闭）
- 每个渠道可单独配置：展示名称、图标、展示分组、排序
- 用户资料字段可从第三方返回结构中映射（支持表达式），用于填充昵称、头像等
- 凭证类配置（密钥等）在界面上默认不可见，仅管理员可查看 / 复制

#### 4.3.4 微信小程序（接口）

小程序内无法跳转网页，改为：小程序调用宿主能力取得临时凭据，提交给 Authloft，Authloft 完成后续流程并返回会话。

#### 4.3.5 微信小程序（扫码）

- 页面展示小程序码，用户用微信扫码后在小程序内完成授权
- 页面通过轮询获取授权状态：待扫描 / 已扫描 / 成功 / 已过期；过期需重新获取
- 小程序码图片通过**可配置的文件存储提供方**保存，存储路径可配置（支持内置变量）
- 该渠道可配置为"登录成功后自动清理码图"；清理在后台异步执行，不影响登录结果
- **Authloft 不负责小程序端的实现**，仅提供生成小程序码与查询 / 写入状态的接口

### 4.4 会话与单点登录（SSO）

#### 4.4.1 会话

- 会话标识通过 Cookie 写入**根域名**，实现同根域名下的会话共享
  - Cookie 名称默认 `al_session`（可配置），默认有效期 **7 天**（可配置）
  - Cookie 属性固定为 `HttpOnly; Secure; SameSite=None`
- 多根域名部署时，在登录与登出时通过后台配置的域名列表，逐个同步会话到各根域名
- 会话令牌自包含、不落盘（不落数据库）；本期不支持服务端主动逐出，架构预留扩展点
- 每次请求均重签会话
- 修改密码、重置密码、管理员禁用，均使该用户全部会话失效；登出仅清除当前客户端的会话 Cookie，已签发令牌在有效期内仍有效（本期无服务端逐出）

#### 4.4.2 登出

- 登出仅清除 Authloft 客户端会话 Cookie（已签发令牌在有效期内仍有效），不影响业务系统已持有的令牌
- 需支持"登出后跳转到指定地址"
- 本期不提供账号注销（account deletion）功能，"注销"一律指登出会话

#### 4.4.3 票据（Ticket）登录

- 用于扫码登录等"一端授权、另一端登录"场景，**不直接对外暴露为独立功能**
- 票据有有效期（默认 10 分钟），用后即销毁，不落数据库
- 支持长轮询查询，单次最长等待 15 秒

#### 4.4.4 SSO 客户端管理

- SSO 客户端仅支持管理后台手动创建
- SSO 客户端用于内部系统，通常不具备独立用户体系，通过共享 Authloft 的 Cookie 传递会话标识
- 客户端属性：客户端标识、密钥、回调地址白名单（支持 `*` 通配）

#### 4.4.5 OIDC 客户端管理

- OIDC 客户端仅支持管理后台手动创建
- OIDC 客户端用于外部系统，可能具备独立用户体系，通过系统获取的 Access Token 访问用户信息
- 客户端属性：客户端标识、密钥、回调地址白名单（支持 `*` 通配）、可用权限范围；授权类型本期固定支持 `authorization_code` 与 `refresh_token`，全部客户端一致，不提供按客户端配置的授权类型开关

---

### 4.5 OIDC 协议

- 需实现标准 OIDC 服务，至少支持：授权码模式、刷新令牌
- 必要端点：服务发现、公钥集（JWKS）、授权、令牌、吊销、用户信息
- 授权端点复用 Authloft 登录流程：先完成登录（含两步验证），再按授权请求生成结果并返回业务系统
- 令牌：
  - 身份令牌（ID Token）包含标准声明（签发者、用户标识、受众、有效期、随机数等）
  - 访问令牌默认采用可自校验格式
  - 刷新令牌可吊销，与客户端和会话绑定
- 标准声明映射：用户标识、昵称、邮箱、手机号、头像及各自的验证状态
- 修改密码将自动吊销该用户全部已颁发令牌
- 吊销令牌仅影响对应令牌，不影响 Authloft 会话与其他令牌

### 4.6 管理后台

| 模块 | 功能 |
|------|------|
| 提供方管理 | 各类外部服务（第三方登录、人机校验、短信、邮件、存储）的列表 / 新建 / 编辑 / 启用 / 排序；表单按类型动态生成；密钥默认掩码，仅管理员可查看或复制 |
| 用户管理 | 列表、详情、禁用 / 启用、重置密码、解绑第三方、解除登录限制、查看登录记录 |
| SSO 客户端管理 | 创建 / 编辑 SSO 客户端、配置回调地址 |
| OIDC 客户端管理 | 创建 / 编辑 OIDC 客户端、配置回调地址与权限范围 |
| 系统配置 | 登录方式开关、两步验证策略、人机校验触发阈值、注册开关、密码策略、会话有效期、Cookie 名称、多域名同步列表、静态资源 CDN 基址（默认 `/assets`）等（具体项见接口文档 §5.6） |
| 事件日志 | 统一记录：登录记录 + 敏感操作（改密、解绑、启用两步验证等），可按类型筛选 |
| 监控 | 运行指标（队列长度 / dropped / flush 耗时）见接口文档 §5.6 |

## 5. 非功能性需求

1. **性能**：登录链路应尽量减少写操作。所有不影响当次登录结果的写入（会话续期、登录日志、审计日志、最近登录时间、失败计数清零、文件清理等）均由系统在后台排队缓慢执行，不拖慢用户操作
2. **安全**
   - 防跨站请求伪造、防重放、防暴力破解
   - 登录过程中的临时状态需防篡改
   - 敏感操作（改密、解绑、启用两步验证）需记入事件日志
3. **可用性**：提供方配置改动即时生效，无需重启
4. **可维护性**：新增一个渠道 / 厂商不应改动已有功能代码；新增一种认证方式是低频事件
